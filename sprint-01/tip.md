# Tips for the Sprint Week

Comment on actions during the first Sprint Week.

During the sprint week, my focus shifted from preparation and learning into active integration, testing, and issue resolution. Each day began with discussions with my teammates to review progress, identify blockers, and ensure that everyone was working towards the same sprint goals. I worked closely with the team to make sure we were all aligned on configuration decisions and that the backend was set up consistently across development environments.

One of my key responsibilities during the sprint was validating the backend API’s connection to the MySQL database and ensuring that this data could be successfully consumed by the frontend application. I regularly ran the backend locally to confirm that database credentials, ports, and environment-specific settings were correct. Where issues occurred, such as failed API responses or connection errors, I communicated findings with my teammates and worked collaboratively to resolve them before they impacted overall progress.

As frontend–backend integration progressed, I supported troubleshooting when API calls failed from the frontend. This involved checking request URLs, confirming that ports and routes matched the running backend, and using browser developer tools to inspect network requests and responses. Several issues were caused by small configuration mismatches. These were resolved by coordinating with the team to standardise configuration values and verify that the backend was properly configured for both local and hosted environments.

Throughout the sprint week, I documented daily activities, challenges, and resolutions in the GitHub work diary. I also supported teammates who encountered setup or configuration issues by helping them verify database connections and backend settings. This collaborative approach helped reduce repeated errors and ensured that the team maintained steady progress.

By the end of the sprint week, these actions contributed directly to achieving a stable, working end-to-end system that could be demonstrated to the client, with reliable database connectivity and successful frontend–backend communication.
